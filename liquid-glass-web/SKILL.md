# Liquid Glass Web 界面开发

将「做成液态玻璃」这类模糊需求，收敛为有视觉层级、真实交互、响应式合同、可用浏览器复核的前端实现。

**重要边界：** 本 skill 只做 Web CSS 模拟（透明、模糊、高光、环境色），不等同于 Apple 原生材质的动态折射、环境感知与自动辅助功能适配。交付时不得宣称实现了 Apple 原生系统材质。

## 工作流

### 1. 先写设计简报，再写代码

把「好看」翻译成可执行的合同，覆盖五个维度，缺一不可：

| 维度 | 必须写清 | 缺失时的风险 |
| -- | --- | --- |
| 用户 | 角色、使用频率、核心动作 | 把运营工具做成营销首页 |
| 现状 | 框架、组件库、变量、测试 | 另起一套风格或破坏约定 |
| 范围 | 可改文件、禁止改变的能力 | 视觉调整膨胀成功能重写 |
| 视觉 | 环境色、材质层级、密度、主次 | 只剩「高级、通透」等空词 |
| 交互 | 默认、错误、加载、成功、取消 | 只交一张静态首页 |
| 验收 | 视口、截图、测试、console、键盘 | 无法判断是否真正可用 |

### 2. 铺五层材质

材质 = 环境 + 填充 + 高光 + 模糊 + 阴影，缺一不可。色卡、CSS 起点、五层材质分级数值、降级写法全部见 [references/material-tokens.md](references/material-tokens.md)。核心纪律：

- 背景用大范围低饱和径向渐变，色彩留在边缘，中央白净。
- 白色覆盖度决定层级：导航最透，阅读面最实。**禁止父容器 `opacity`**，alpha 只加在背景色上，文字图标保持不透明。
- 禁止玻璃叠玻璃；玻璃只用于导航、工具条、浮层与少量卡片，内部控件用简单填充和细边框。
- 参数一律提取成 CSS 变量。

### 3. 保证信息密度

- 标题负责定位，不承担营销口号；避免巨大 Hero。
- 统一 8/12/16/24px 间距阶梯；表面圆角 18–22px，控件 10–12px。
- 只有主操作使用高饱和色，次要操作回到图标或弱填充。
- 卡片扫描顺序固定为：预览 → 标题 → 描述 → 状态 → 动作。

### 4. 交互合同：视觉暗示 = 真实命中范围

- 视觉上像按钮的区域必须整体可点、可键盘操作；用原生 `button` / `label` / `dialog`，不用带点击事件的 `div` 模拟。
- 选择文件、生成预览、发布是三个不同状态，画清状态机，不自动串联。
- 补齐空态、错误、加载、成功、取消路径；搜索无结果时给空态与清除筛选入口，不留假按钮。

### 5. 响应式是结构重排，不是等比缩小

固定检查 1440 / 1280 / 768 / 390(375) 四档：

- 1440：侧栏 + 三列卡片 + 单行工具条
- 1280：两列卡片，工具条允许换行
- 390：导航横排、卡片单列、搜索与操作换行，保持触控面积
- 不靠缩小正文硬塞布局；不得出现横向溢出。

### 6. 渐进增强必须有

`backdrop-filter` 不支持的浏览器用实色底；`prefers-reduced-transparency`、`prefers-contrast: more`、`prefers-reduced-motion` 各有对应分支。完整代码见 material-tokens.md。显式 fallback 是实现的一部分，不是锦上添花。

### 7. 验收与交付

- 逐条过交付前检查清单（见 prompt-templates.md 末尾）。
- 有浏览器工具时，在 1440、768、390 下截图并观察 console、键盘焦点。
- **如实报告**：实现、测试、浏览器实测、未验证项分开写，不把自检推断写成已验证。
- 遇到质量问题先查 [references/pitfalls.md](references/pitfalls.md)（现象 → 根因 → 修复速查表）。

## 生成提示词模板

- 从零生成单文件原型：用 [references/prompt-templates.md](references/prompt-templates.md) 中的首轮生成提示词，替换其中的主题与内容即可。
- 把单文件原型迁移到现有前端：用其中的组件化迁移提示词（token / 材质 primitive / 控件 / 领域组件四层拆分，不新增产品能力）。

## 调参与反馈纪律

- 一次只改 2–4 个变量，且反馈要量化：「右侧蓝色 alpha 从 .32 降到 .22」「卡片阴影 Y 从 20px 降到 12px」，不说「再高级一点」。
- 每轮迭代在固定视口截图对比，确认改动只影响目标区域。
