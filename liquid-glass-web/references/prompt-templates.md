## 首轮生成提示词（单文件原型）

> 请制作一个受 macOS 26 Liquid Glass 启发的「[主题，如：团队项目工作台]」Web 页面。
>
> 直接交付完整可运行的页面，不要只给设计建议、局部代码或图片。
>
> 【交付形式】
> - 生成自包含的 index.html，CSS 与 JavaScript 内嵌，保存后可直接用浏览器打开。
> - 不依赖构建工具、CDN、远程字体、远程图片或后端。使用系统字体和内联图标。
> - 能写文件时在允许的输出目录创建文件并告知路径；如果当前目录已有工程，另建独立演示文件，不覆盖已有入口。
>
> 【用户与内容】
> - 用户是 [角色，如：每天查看项目进展、寻找资料并执行操作的团队成员]。
> - 首屏直接显示 [主界面]，布局为 [如：左侧导航、顶部路径与主内容区]。
> - 包含：[导航项]、[页头：标题 + 简短描述 + 一个主按钮]、[紧凑统计]、[工具条：搜索 + 筛选 + 视图切换]、[若干标注「示例」的内容卡片]、[新建弹窗：表单字段 + 取消 + 创建]。
> - 数据只保存在页面内存中，刷新恢复初始值，用一句简短文案告知用户。
>
> 【视觉要求】
> - 整体清透、安静、紧凑，适合高频扫描，避免巨大营销标题与无意义装饰。
> - 低频环境光左暖杏、右冷蓝，中间保持白净。色彩：页面底色 #F7F9FC；暖杏 #FFD29D；冷蓝 #A0CFFF；主操作蓝 #2868D8；正文 #202C40；次要文字 #5B6D85。
> - 玻璃表面 CSS 起点：
>   background: linear-gradient(145deg, rgba(255,255,255,.78), rgba(255,255,255,.42));
>   border: 1px solid rgba(255,255,255,.82);
>   box-shadow: inset 0 1px 0 rgba(255,255,255,.84), 0 18px 48px rgba(55,83,118,.14);
>   -webkit-backdrop-filter: blur(24px) saturate(130%);
>   backdrop-filter: blur(24px) saturate(130%);
> - 参数提取成 CSS 变量：导航与工具条更透明，卡片用半透明白色填充并减少额外模糊；模态框提高白色覆盖，长文本区接近实色。
> - 不要给父容器设置 opacity，文字、图标与输入内容必须保持清晰。
> - 避免玻璃叠玻璃，内部控件使用简单填充和细边框。
> - 统一 8/12/16/24px 间距；表面圆角约 18～22px，控件约 10～12px。
> - 主色集中强调主操作，状态同时用文字表达。
>
> 【真实交互】
> - 搜索实时过滤名称和描述；筛选、收藏与视图切换可以组合使用。
> - 切换视图保留搜索和筛选条件，卡片与列表使用同一份数据。
> - 搜索无结果时显示空态与清除筛选入口，不留假按钮。
> - 新建弹窗使用原生 dialog、button、label、input：
>   - 名称去掉首尾空格后不能为空，非法输入有明确提示。
>   - 创建成功后更新列表与统计，让新项目可见；必要时清除阻挡它的筛选并提供反馈。
>   - 取消或 Escape 不创建项目。
>   - 打开时焦点进入表单，关闭后回到触发按钮。
> - 视觉上可点击的区域与真实命中范围一致，图标按钮有可访问名称。
>
> 【响应式与降级】
> - 1440px：[布局合同]；768px：[布局合同]；390px：[布局合同]。
> - 不靠缩小正文硬塞布局，不能出现页面横向溢出；保持可见键盘焦点和合理触控面积。
> - 不支持 backdrop-filter 时用实色底；prefers-reduced-transparency 或 prefers-contrast: more 时提高覆盖和边界清晰度；prefers-reduced-motion 时减少动画，不做持续装饰动画。
>
> 【完成前验证】
> - 检查搜索、筛选、收藏、新建成功/错误/取消，以及键盘操作。
> - 有浏览器工具时在 1440、768、390px 下检查布局、截图并观察控制台；没有工具时如实列出未实测项，不把自检推断写成已验证。
> - 交付完整 HTML，附简短打开方式、已实现交互和实测结果。
> - 效果属于 Web CSS 模拟，不要宣称实现了 Apple 原生系统材质。

## 组件化迁移提示词（接入现有前端）

> 请先读取仓库规则、现有页面、组件库、样式变量和测试，总结信息架构与行为合同；不要新增后端能力或改变数据语义。
>
> 目标：把现有操作型 Web 界面调整为受 macOS 26 Liquid Glass 启发的清透玻璃风格。用户需要高频扫描、比较和操作，所以优先保证紧凑、清晰、稳定。
>
> 视觉约束：
> - 左侧低饱和暖杏、右侧低饱和冷蓝，中央阅读区白净；
> - 玻璃只用于导航、工具条、浮层与少量卡片，禁止玻璃叠玻璃；
> - 导航比卡片透明，模态框与长文本区更接近实色；
> - 禁止父容器 opacity；backdrop-filter 必须有实色降级；
> - 处理 reduced-transparency、contrast 和 reduced-motion。
>
> 交互约束：视觉上像按钮的区域必须整体可点且可键盘操作；[状态 A]、[状态 B]、[状态 C] 是三个不同状态。
>
> 每轮只改一组变量；在 1440、1280、768、390 宽度截图；最后运行既有测试并检查 console、焦点、错误和取消路径。
>
> 已确认单文件交互稿的布局和状态流后，按以下步骤迁移：
> 1. 列出视觉 token、通用材质、基础控件、领域组件和演示专属逻辑。
> 2. 复用现有组件、图标和测试；不要复制模拟延时、假数据或候选功能。
> 3. 保持接口、路由、权限和状态语义不变。
> 4. 材质类按 nav / toolbar / card / modal / reading 五级分级（数值见 references/material-tokens.md）。
> 5. 修复视觉暗示与点击范围不一致，优先使用原生语义控件。
> 6. 补 fallback 与辅助设置分支。
> 7. 分开报告实现、单测、构建、浏览器路径和未验证项。

## 交付前快速检查清单

- [ ] 用户、任务、范围和禁区已写清
- [ ] 演示能力与真实能力已区分
- [ ] 没有父容器 opacity
- [ ] 没有大面积玻璃叠玻璃
- [ ] 材质按导航 / 工具条 / 卡片 / 模态框 / 阅读面分级
- [ ] 视觉按钮真实可点且可键盘操作
- [ ] 选择、提交、发布没有混淆
- [ ] fallback 与辅助设置已验证
- [ ] 桌面、中等和手机视口已复核
- [ ] 实现、测试、浏览器和未验证项分开报告
