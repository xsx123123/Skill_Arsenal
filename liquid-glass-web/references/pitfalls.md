## 现象 → 根因 → 修复 → 预防

| 现象 | 根因 | 修复 | 预防 |
| -- | -- | -- | -- |
| 玻璃像灰塑料 | 只提高 blur | 补环境、alpha 填充、高光和柔影 | 五层分别设变量 |
| 右侧蓝色抢内容 | 渐变范围/alpha 过大 | 缩小色光，提高中央白色覆盖 | 边缘有色、中央可读 |
| 卡片松散难扫 | 把风格等同大圆角大留白 | 固定信息顺序和间距阶梯 | 先验收工作流 |
| 上传区只有文字可点 | 视觉与 DOM 命中区不一致 | 用原生按钮/label 扩大真实范围 | 键盘和触摸都验 |
| 选择文件后像已发布 | 选择、生成、公开混为一体 | 拆分 selected / ready / live | 先画状态机 |
| 手机只缩小桌面稿 | 没有重排合同 | 导航横排、工具换行、卡片单列 | 固定小屏证据 |
| console 有 favicon 404 | 默认图标资源缺失 | 补图标或明确记录 | 区分噪声与功能失败 |

## 证据报告纪律

- 截图只是证据矩阵的一列，最低覆盖：视口（1440 / 1280 / 768 / 390）、状态（默认、筛选、模态框、错误、加载、成功）、输入（鼠标、Tab/Enter/Escape）、浏览器（console error/warning、失败请求）、辅助设置（焦点、减少透明度/动态、高对比度）。
- 交互后重新获取快照引用，DOM 重渲染可能让旧引用失效。
- 截图通过不能替代单测、构建和 E2E；不能把本地示例路径升级为生产环境证明。
- 明确写清本次复核的范围与日期，以及该范围**不**覆盖什么（如后端接入、生产发布、全部用户验收）。
- 区分噪声与功能失败：favicon 404 之类的资源缺失要记录，但不应与功能性错误混为一谈。
